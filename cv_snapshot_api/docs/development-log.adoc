=== 추가 또는 변경된 동작

. `/startserver` POST JSON을 검사하고 1024~65535 포트의 AppNetworkManager TCP 서버
  시작을 요청한다.
. 새 연결 직후 이미지를 보내지 않고, client별 버퍼에 분할된 HTTP header를 모은다.
. `GET /image/jpg`만 허용하며 잘못된 method, path, request와 과대 header에 오류
  status를 보낸다.
. AppInfo 이벤트에서 `app_id`를 확보한다.
. `eAppSnapshotJpeg`로 `../storage/opencvcapter_snapshot.jpg`에 현재 프레임을 저장한다.
. `FrameProcessor`가 grayscale decode, GaussianBlur, Canny와 JPEG encoding을 담당한다.
. JPEG 응답에 정확한 Content-Length, `image/jpeg`, no-store, CORS와 connection close
  header를 넣는다.
. 동시 처리 요청에는 503을 반환하도록 busy 상태를 추가했다.
. 테스트 웹은 서버 시작과 이미지 요청을 분리하고 cache-buster로 반복 요청한다.

=== API 영향

[source,text]
----
POST /opensdk/{app_id}/startserver
GET  http://{camera-ip}:{port}/image/jpg
----

endpoint와 method는 레퍼런스 호환이다. `/startserver`는 성공 시 JSON과 HTTP 202를
반환하며, 같은 포트 재요청은 200, 다른 포트 재설정은 409를 반환한다. 포트 재설정은
앱 재시작 후 수행한다.

=== 빌드 및 패키징 변경

* component source에 `frame_processor.cc`를 추가했다.
* AppNetworkManager include, runtime package와 network scheduler를 추가했다.
* OpenCV include/link 경로와 core, imgproc, imgcodecs 링크를 추가했다.
* install 시 `libopencv_*.so*`를 앱 `libs`에 포함한다.
* 실제 SDK 설정에서 CV5 toolchain은 GCC 12.1 경로다. 초기 대화에서 예상한 GCC 9.4.0과
  다르므로 현재 SDK 파일을 기준으로 기록했다.

=== 수행한 검증

* 수정 대상 JSON 5개를 PowerShell `ConvertFrom-Json`으로 파싱했다.
* 테스트 HTML의 script를 추출해 Node.js `--check`로 문법 검사했다.
* OpenCV 9개 library의 ELF magic, 64-bit class, little-endian과 AArch64
  `e_machine=183`을 검사했다.
* source에서 `/startserver`, `/image/jpg`, `eServerData`, `eAppSnapshotJpeg`, OpenCV
  link가 연결됐는지 검색했다.
* Windows 호스트에서 Docker 명령 존재 여부를 확인했다.

변경 이전 산출물이므로 새 구현의 성공 증거가 아니다.

`CloseClient()`의 `eCloseClient` 전송에서 payload가 없는데도 네 번째 인자로

  `_CMAKE_LINKER_PUSHPOP_STATE_SUPPORTED:INTERNAL=TRUE`로 정상임을 확인했다.
* `docker-compose.yml`이 기존 build 디렉터리를 유지한 채 `cmake`를 실행하는 구조임을
  확인했다.

이번 실행은 CMake cache 읽기 단계에서 실패했다. 수정된 `sample_component.cc`는

쓰기 결과가 다음 실행에 남을 수 있다. 소스와 `app/3rd_party`는 유지하되 build cache는
환경별로 새로 생성해야 한다.
